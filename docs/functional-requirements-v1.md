# وثيقة المتطلبات الوظيفية للنظام

> تحديث التنفيذ: بدأ بناء التطبيق بتوجيه المستخدم اللاحق في 15 أكتوبر 2026. أي ذكر أدناه لمرحلة «الوثائق فقط» يصف الاعتماد السابق؛ حالة التنفيذ الحالية في [سجل التنفيذ](implementation-progress.md).

**الإصدار الأول — متطلبات وقرارات معتمدة**

**تاريخ تثبيت القرارات:** 15 أكتوبر 2026.

**مرجع الاعتماد:** [سجل القرارات المعتمدة](approved-decisions-v1.md)، ويشمل القرارات Q1–Q31. [خطة التطوير](development-plan-v1.md) تفصل مراحل التنفيذ والقبول.

**اسم المشروع:** نظام إدارة المحلات التجارية والمحاسبة.

**الفئة المستهدفة:** المحلات التجارية الصغيرة والمتوسطة بمختلف أنشطتها.

**هدف النظام:** توفير نظام متكامل لإدارة العمليات التجارية والمخزون والحسابات، يتميز بسهولة الاستخدام ويعتمد على أسس محاسبية صحيحة، مع قابلية التوسع مستقبلًا.

**نطاق التشغيل المعتمد:** السوق الأول اليمن؛ تطبيق Flutter لجهاز واحد لكل محل يعمل دون إنترنت، بأولوية إطلاق Windows ثم macOS وAndroid. تبدأ التجربة بمحل أدوات منزلية أو كهربائية، ويستخدم الموظفون حسابات محلية على الجهاز نفسه. نقل العمل لجهاز بديل بالنسخ والاستعادة مع إيقاف استخدام النسخة القديمة؛ المزامنة ودمج تعديلات جهازين خارج نطاق الإصدار الأول.

**اللغة:** واجهة عربية مع دعم أسماء المنتجات والأطراف والملاحظات بالعربية أو الإنجليزية، وتجهيز النصوص لإضافة واجهة إنجليزية لاحقًا. واجهة Windows مناسبة للجداول ولوحة المفاتيح.

**حالة الوثيقة:** تصف المتطلبات المعتمدة؛ التحديث الحالي لتثبيت القرارات في الوثائق فقط، ولا يمثل تنفيذًا للميزات أو قبولًا ميدانيًا لها.

## أولًا: الميزات الأساسية للإصدار الأول

### 1. المنتجات والمخزون

- إدارة المنتجات والتصنيفات والباركود.
- إدارة أسعار الشراء والبيع.
- دعم وحدات القياس المختلفة (حبة، كرتون، وغيرها).
- دعم المتر والكيلوجرام والكميات الكسرية، بمعامل تحويل خاص بكل منتج وإعداد يحدد قبول الكسور؛ يمكن منع كسر الحبة.
- متابعة كميات المنتجات وحركات المخزون.
- الجرد وتسوية فروقات المخزون والتالف.
- احتساب تكلفة المخزون باستخدام المتوسط المرجح المتحرك.
- منع المخزون السالب، مع دعم الاستلام السريع للبضائع قبل تسجيل فاتورة الشراء النهائية.

### 2. المبيعات

- إنشاء فواتير بيع نقدية وآجلة وبدفع جزئي.
- الخصومات على المنتجات والفواتير.
- جمع المنتجات والخدمات في الفاتورة نفسها، وإدراج مواد تنفيذ الخدمات كبنود منتجات مستقلة تخصم من المخزون.
- السماح بفاتورة نقدية دون اختيار عميل؛ اختياره اختياري لحفظ مشترياته وإلزامي إذا بقي مبلغ آجل.
- توزيع الدفع على عدة حسابات نقدية أو بنكية بعملة المحل، مع إبقاء المتبقي آجلًا عند وجوده.
- منح البائع الخصم ضمن حد يحدده المالك؛ تجاوز الحد أو تغيير السعر يدويًا يحتاج صلاحية إضافية، مع تسجيل المستخدم والخصم والسعر الفعلي.
- مرتجعات المبيعات الكلية والجزئية.
- ربط المرتجع بالفاتورة الأصلية ومنع تجاوز الكمية أو المبلغ القابل للإرجاع؛ عمليات ما قبل استخدام البرنامج تُعالج بتسوية مستقلة موثقة دون فاتورة وهمية.
- إعادة المرتجع الصالح للبيع إلى المخزون المتاح؛ تسجيل استلام التالف وإتلافه بأثر موثق دون إتاحته للبيع.
- تخفيض غير المسدد من الفاتورة أولًا عند المرتجع، ثم إتاحة رد الفائض من حساب محدد أو إبقائه رصيدًا لصالح العميل.
- طباعة الفواتير ومشاركتها.
- التحديث التلقائي للمخزون والحسابات عند اعتماد الفاتورة.
- تصحيح وإلغاء الفواتير المعتمدة مع الاحتفاظ بسجل العمليات.

### 3. نقاط البيع (POS)

- واجهة بيع سريع اختيارية بحسب طبيعة النشاط.
- إضافة المنتجات يدويًا أو باستخدام الباركود.
- دعم الدفع النقدي والآجل والجزئي.
- طباعة فواتير البيع.
- الربط المباشر بالمبيعات والمخزون والمحاسبة.
- تطبيق قواعد الأسعار والخصومات والصلاحيات نفسها المعتمدة في شاشة البيع.

### 4. المشتريات

- إنشاء فواتير شراء نقدية وآجلة وبدفع جزئي.
- إدارة مرتجعات المشتريات.
- تسجيل أسعار الشراء وتكاليف المنتجات.
- دعم استلام المنتجات قبل تسجيل الفاتورة النهائية.
- إدخال تكلفة تقديرية إلزامية عند الاستلام السريع، مع اقتراح آخر تكلفة معروفة وإتاحة تعديلها، ثم تسوية الفرق عند وصول الفاتورة النهائية دون تكرار كمية الاستلام.
- إضافة الشحن والنقل إلى تكلفة المنتجات اختياريًا، وتوزيعهما افتراضيًا حسب قيمة المنتجات، وفصلهما عن المصروفات التشغيلية.
- تقسيم الدفع بين الحسابات بعملة المحل، وتطبيق قواعد مرجع المرتجع وتسوية المستحقات والأرصدة لصالح الطرف على مرتجعات المشتريات.
- تحديث المخزون وتكلفته وحسابات الموردين تلقائيًا.

### 5. العملاء

- إدارة بيانات العملاء وحساباتهم.
- إمكانية كون الطرف نفسه عميلًا وموردًا بسجل بيانات واحد وحساب مستقل لكل دور، دون مقاصة تلقائية بينهما.
- متابعة الأرصدة والديون المستحقة.
- تسجيل دفعات العملاء وسندات القبض.
- السداد على الرصيد العام دون اشتراط تحديد فاتورة.
- إمكانية ربط الدفعات بالفواتير يدويًا أو تلقائيًا.
- التخصيص التلقائي للأقدم استحقاقًا أولًا، مع عرض التوزيع قبل الاعتماد وإتاحة التخصيص اليدوي أو ترك الدفعة على الرصيد العام.
- قبول الدفعات المقدمة والزائدة وإظهار غير المخصص رصيدًا لصالح العميل يمكن استخدامه لاحقًا أو رده بسند.
- كشف حساب تفصيلي للعميل.
- تسجيل الرصيد الافتتاحي.

### 6. الموردون

- إدارة بيانات الموردين وحساباتهم.
- متابعة المبالغ المستحقة للموردين.
- تسجيل التسديدات وسندات الصرف.
- السداد على الرصيد العام أو على فواتير محددة.
- دعم التخصيص التلقائي للأقدم استحقاقًا أولًا أو اليدوي، وعرض التوزيع قبل الاعتماد، مع دعم الدفعات المقدمة والزائدة والأرصدة غير المخصصة واستردادها بسند.
- كشف حساب تفصيلي للمورد.
- تسجيل الرصيد الافتتاحي.

### 7. الصندوق والحركات المالية

- إدارة الصندوق والحسابات النقدية والبنكية.
- سندات القبض والصرف.
- توزيع مبلغ السند بين عدة حسابات بعملة المحل نفسها.
- التحويل بين الصناديق والحسابات.
- منع اعتماد صرف أو تحويل أو رد نقدي يتجاوز رصيد الصندوق أو الحساب البنكي المتاح.
- متابعة الأرصدة والحركات المالية.
- مطابقة النقدية وإغلاق الصندوق.
- تسجيل إضافات رأس المال والمسحوبات الشخصية.

### 8. المصروفات

- تسجيل المصروفات التشغيلية.
- تصنيف المصروفات حسب النوع.
- تحديد الحساب الذي دُفع منه المصروف.
- تسجيل أجور الفنيين وتكاليف تنفيذ الخدمات كمصروفات؛ لا يتضمن الإصدار الأول تتبع تكلفة وربح كل مهمة منفردة.
- تقارير المصروفات حسب الفترة والتصنيف.

### 9. الأرصدة الافتتاحية

- تسجيل أرصدة الصندوق والبنوك.
- تسجيل أرصدة العملاء والموردين.
- إدخال المخزون الافتتاحي وكمياته وتكلفته.
- دعم إدخال الأرصدة تدريجيًا.
- السماح ببدء البيع بعد إدخال الصندوق والأصناف المطلوبة، واستكمال بقية الأصناف والعملاء والموردين لاحقًا.
- افتتاح كل صنف قبل أول حركة عليه؛ الفروقات بعد بدء حركته تُعالج بتسوية موثقة بدل تغيير افتتاحه مباشرة.
- إنشاء قيود افتتاحية متوازنة باستخدام حساب تسوية مؤقت.
- مراجعة واعتماد الأرصدة قبل إقفال التسوية الافتتاحية.

### 10. النظام المحاسبي

- دليل حسابات أساسي قابل للتوسع.
- تطبيق نظام القيد المزدوج (مدين ودائن).
- إنشاء القيود اليومية تلقائيًا من العمليات.
- دفتر الأستاذ العام.
- إدارة حسابات الأصول والالتزامات وحقوق الملكية والإيرادات والمصروفات.
- احتساب تكلفة البضاعة المباعة.
- القيود العكسية والتصحيحات المحاسبية.
- ربط القيود بالمستندات الأصلية.
- سجل مراجعة للحركات والتعديلات.
- أثر المستند القديم على المخزون والتكلفة يكون عند اعتماده الحالي، مع حفظ تاريخ الورقة للمرجع، دون إعادة كتابة تكلفة المبيعات المرحلة في التسلسل السابق.
- اعتماد منزلتين عشريتين للمبالغ وثلاث للكميات الكسرية وست للحساب الداخلي لتكلفة الوحدة، مع تقريب موحد وتسوية آلية لفروقه واختبار الحدود مع التحويل والمتوسط قبل تثبيت التنفيذ.

**ملاحظة:** تعمل المحاسبة تلقائيًا في الخلفية، دون إلزام المستخدم العادي بالتعامل مع القيود اليومية.

### 11. التقارير

- تقارير المبيعات والمشتريات والمرتجعات.
- تقارير الأرباح والخسائر.
- تقارير المخزون وحركة المنتجات وقيمتها.
- تقارير أرصدة العملاء والموردين.
- تقارير الصندوق والحركات المالية.
- تقارير المصروفات.
- إظهار إيرادات الخدمات ومصروفاتها، دون تقرير تكلفة وربح لكل مهمة منفردة في الإصدار الأول.
- كشوف الحسابات.
- ميزان المراجعة ودفتر الأستاذ.
- تصدير التقارير بصيغ PDF وExcel.

### 12. الإعدادات والإدارة

- إعداد بيانات المحل والعملة الأساسية.
- اختيار عملة أساسية واحدة للمحل: الريال اليمني (YER) أو الريال السعودي (SAR).
- إتاحة تصحيح اختيار العملة قبل أول عملية مالية، ومنع تغييره بعدها.
- إدارة المستخدمين والصلاحيات.
- الأدوار الأولية: مالك بجميع الصلاحيات، وبائع للبيع والقبض ضمن صلاحياته دون رؤية التكلفة والأرباح أو إلغاء المستندات المعتمدة، ومحاسب للمشتريات والمصروفات والتسويات والتقارير.
- حساب محلي وكلمة مرور لكل مستخدم، ورمز استرداد للمالك يُنشأ عند الإعداد ويحفظ خارج الجهاز ويعمل دون إنترنت؛ استرداد دخول الموظفين من حساب المالك.
- ترقيم الفواتير والسندات.
- إعدادات النظام المحاسبية الأساسية.
- النسخ الاحتياطية واستعادة البيانات.
- نسخ تلقائي إلى مجلد يختاره المستخدم كل ساعة أثناء وجود تغييرات، وعند بدء التطبيق إذا فات الموعد، وقبل التحديث والاستعادة؛ لا يعتمد على فتح صفحة النسخ.
- دعم النسخ إلى USB عند توفره، وعرض وقت آخر نسخة ناجحة وآخر نسخة خارجية، والتنبيه عند تأخر النسخة الخارجية.
- تشفير النسخ بمفتاح استرداد يحتفظ به المالك خارج الجهاز، واختبار الاستعادة أثناء الإعداد وعلى جهاز بديل؛ فقد المفتاح قد يمنع الاستعادة.
- فصل مفتاح فك تشفير النسخ عن رمز استرداد الدخول.
- سجل العمليات والتعديلات.

### 13. الخدمات

- الخدمات ضرورية ومشمولة في الإصدار الأول كبنود بسعر وكمية ووصف، مثل التركيب والصيانة البسيطة.
- يمكن جمع الخدمة والمنتجات في فاتورة واحدة، ولا تحرك الخدمة المخزون تلقائيًا؛ موادها تُدرج كبنود منتجات مستقلة.
- تسجيل تكاليف التنفيذ وأجور الفنيين كمصروفات، دون إدارة مستقلة لتكلفة وربح كل مهمة.
- رد قيمة الخدمة كليًا أو جزئيًا بمستند مرتبط بالفاتورة وسبب، بصلاحية المالك أو المحاسب، دون حركة مخزون ودون تجاوز المتبقي القابل للرد.
- إدارة استلام أجهزة الصيانة وأوامر العمل والفنيين والمواعيد والاستهلاك التلقائي للمواد مؤجلة.

## ثانيًا: قواعد العمل الأساسية

هذه القواعد يجب أن يلتزم بها النظام في الإصدار الأول.

| العملية | القاعدة المعتمدة |
| --- | --- |
| البيع والشراء | دعم الدفع الكامل والجزئي والآجل. |
| المخزون | منع خروج كمية أكبر من المتوفر للمنتجات المخزنية. |
| استلام البضائع | السماح بالاستلام قبل فاتورة الشراء، مع تسوية التكلفة لاحقًا. |
| دفعات العملاء والموردين | إمكانية السداد على الرصيد العام دون ربط إلزامي بالفواتير. |
| الأرصدة الافتتاحية | إدخال تدريجي مع قيود متوازنة ومراجعة قبل الاعتماد النهائي. |
| الفواتير المعتمدة | عدم تعديل القيود والحركات المرحلة مباشرة؛ التصحيح بمستندات مرتبطة. |
| القيود المحاسبية | توليد تلقائي من العمليات، مع تساوي إجمالي المدين والدائن. |
| المخزون والمحاسبة | توحيد أثر الفواتير والمرتجعات والتسويات على المخزون والحسابات. |
| سلامة البيانات | الحفاظ على تاريخ العمليات وسجل التعديلات وإمكانية التتبع. |
| الخدمات | بنود في الفاتورة دون حركة مخزون؛ مواد التنفيذ بنود منتجات مستقلة وتكاليف التنفيذ مصروفات. |
| العملة | عملة واحدة YER أو SAR، مع منع تغييرها بعد أول عملية مالية. |
| الدقة | منزلتان للمبالغ، وثلاث للكميات الكسرية، وست لحساب تكلفة الوحدة داخليًا، مع اختبار التقريب والتسويات. |
| الأطراف | الطرف قد يكون عميلًا وموردًا بحسابين مستقلين دون مقاصة تلقائية. |
| تخصيص الدفعات | تلقائي للأقدم استحقاقًا أو يدوي أو على الرصيد العام؛ التخصيص لا يسجل قبضًا أو صرفًا جديدًا. |
| الأرصدة النقدية | منع الصرف والتحويل والرد بما يتجاوز رصيد الصندوق أو البنك. |
| التواريخ | حفظ تاريخ الورقة للمرجع؛ أثر المخزون والتكلفة عند الاعتماد الحالي دون إعادة كتابة التكلفة السابقة. |
| المرتجعات | مرجع أصلي إلزامي؛ تخفيض غير المسدد أولًا ثم رد الفائض أو إبقاؤه رصيدًا لصالح الطرف. |
| النسخ والاسترداد | نسخ مشفرة كل ساعة عند وجود تغييرات ونسخ خارجية عند توفر الوسيط، مع فصل مفتاح النسخ عن رمز استرداد الدخول. |

## ثالثًا: الميزات المؤجلة للإصدارات المستقبلية

1. إدارة الفروع والمخازن المتعددة.
2. إدارة الأصول الثابتة والإهلاك.
3. دعم العملات المتعددة وفروقات الصرف.
4. إدارة تواريخ الصلاحية والدفعات المخزنية.
5. إدارة الورديات والكاشيرات المتقدمة.
6. القيود اليومية اليدوية والإقفال المحاسبي المتقدم.
7. القوائم المالية المتقدمة والموازنات.
8. إدارة الضرائب والتكاملات الضريبية حسب السوق.
9. أدوات استيراد وترحيل البيانات من الأنظمة الأخرى.
10. إدارة أوامر الصيانة واستلام الأجهزة والفنيين والمواعيد.
11. تتبع تكلفة وربح كل مهمة خدمة والاستهلاك الآلي لموادها.
12. واجهة استخدام إنجليزية كاملة؛ تبقى بيانات المنتجات والأطراف والملاحظات قابلة للإدخال بالعربية أو الإنجليزية في الإصدار الأول.

## رابعًا: قرارات التنفيذ والإطلاق

- العمل على مراحل دون موعد إطلاق ملزم حاليًا، ومراجعة محاسب قبل التجربة ببيانات حقيقية.
- تجربة أولية لدى محل أدوات منزلية أو كهربائية، ثم إطلاق Windows بعد استيفاء شروط القبول في خطة التطوير، وإصدار macOS وAndroid تدريجيًا بعد قبول كل منصة.
- تأجيل بناء الترخيص والتفعيل إلى ما بعد أول دورة تشغيل؛ يُحسم نموذج البيع والتفعيل قبل التوزيع التجاري مع الحفاظ على التشغيل اليومي دون إنترنت.
- يبقى تحديد الأجهزة والطابعات الفعلية ومصفوفة الصلاحيات التفصيلية وسياسة الاحتفاظ بالنسخ وقواعد توزيع خصم الفاتورة من مهام التحضير والتنفيذ في حدود القرارات المعتمدة.
